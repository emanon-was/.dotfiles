# グローバル指示

## 調査と回答

- 推測に基づいて回答しない。不明な点は、利用可能なファイル、コマンドの出力、一次情報を調査して確認する。
- 調査しても確定できない場合は、不明であることを明示してユーザーに確認する。

## セッション開始時の herdr 確認

- 作業に入る前に、このエージェントが herdr 内かを確認し、結果を短く報告する。CLI がインストールされているだけで、herdr 内と判断しない。
- `HERDR_ENV=1` の場合は、`herdr --skill` で組み込みスキルを読み、そこに従って読み取り専用の操作で所属を確認する。`HERDR_WORKSPACE_ID` / `HERDR_TAB_ID` / `HERDR_PANE_ID` と実際の workspace / tab / pane が一致することを確認する。
- herdr の環境変数がすべて未設定または空の場合は、herdr 外として通常のツールで作業する。コンテキストが不完全、または実際の所属と一致しない場合は、判定不能であることを明示する。
- `herdr --skill` が失敗した場合は、読み込めなかったことを報告する。スキルの内容や対象を推測して端末操作を行わない。判定やスキル不足に依存しない作業は続けてよい。

## プロジェクトルートと作業規範

- 作業を始める前に、現在のディレクトリがプロジェクトに属しているか確認する。現在のディレクトリまたは親ディレクトリに Git ワークツリーまたは `flake.nix` がある場合は、プロジェクトとして扱う。
- Git ワークツリー内では Git のトップレベルをプロジェクトルートとする。それ以外では、現在のディレクトリから最も近い、`flake.nix` が存在するディレクトリをルートとする。
- ルートに `AGENTS.md` がない場合は、作業を始める前に作成する。確認できたプロジェクト固有の構成、規約、検証コマンドだけを記載し、不明な内容を推測して記載しない。

## ツールの宣言先

宣言先は作業場所ではなく用途で決める。AI エージェント用の共通 flake は `$CODEX_HOME/flake.nix` とし、`CODEX_HOME` が未設定の場合は `~/.codex/flake.nix` を使用する。

- プロジェクト自体のビルド、実行、テスト、整形、開発に必要なツールは、プロジェクトの `flake.nix` に宣言する。
- AI エージェントが利用するツールは、作業場所にかかわらず共通 flake に宣言する。直接実行するすべての CLI が対象であり、シェル、標準的なユーティリティ、ビルド、テスト、整形、検査のコマンドを含む。
- 調査、ファイル操作、端末操作など、AI の作業のためだけに使うツールは、プロジェクトの flake に追加しない。AI が実行するという理由だけで、プロジェクトに必要なツールを取り除かない。両方の用途があるツールは、双方に宣言してよい。
- シェル組み込みコマンドを使う場合は、そのシェルを共通 flake に宣言する。組み込みコマンドを個別に宣言する必要はない。
- Nix 環境外でも、ツールと依存関係はそれぞれ所定の flake に宣言する。宣言されていないツールを、その場限りの環境構築コマンドで導入して使用しない。

## プロジェクトの Nix 開発環境

### `/etc/nixos` を対象とする場合の例外

- `/etc/nixos` 自体または配下を対象とする作業では、この節の flake・`.envrc` の自動作成と開発環境追加のルールを適用しない。作業ディレクトリが別の場所でも、この例外を優先する。
- 作業ツールのために `/etc/nixos` 以下へ `flake.nix`・`flake.lock`・`.envrc` を作成したり、既存ファイルへ開発環境の設定を追加したりしない。AI のツールは共通 flake で管理する。
- 既存のシステム用 flake や `.envrc` は保持する。利用者が明示的に依頼した変更は行ってよい。

### flake と direnv の設定

- プロジェクトに `flake.nix` がない場合は、ルートに作成する。
- ルートに `flake.nix` があり、`nix`、`direnv`、`nix-direnv` の `use flake` が利用可能な場合は、ルートの `.envrc` に `use flake` を記載する。flake を新規作成した場合も同様とし、既存の `.envrc` の内容は保持して必要な記述を追加する。
- `.envrc` が flake の開発環境を指定している場合は、プロジェクトのツールをその開発環境に追加する。指定がなければデフォルトの dev shell に追加する。
- プロジェクトの `.envrc` を AI エージェント用の共通 flake に向けない。

## flake 変更時の検証

- 入力を追加または変更した場合は、`flake.lock` を更新して同期する。既存の入力を不必要に更新しない。
- `flake.nix` を変更した場合は、構文評価、`nix flake check`、プロジェクトで定められたビルドやテストを実行する。実行できない項目は、その項目と理由を報告する。
