# グローバル指示

## 正確性

- 推測に基づいて回答しない。
- 不明な点は、利用可能なファイル、コマンドの出力、一次情報を調査して確認する。
- 調査しても確定できない場合は、推測で補わず、不明であることを明示してユーザーに確認する。

## プロジェクトの判定と依存関係

- 作業を始める前に、現在のディレクトリがプロジェクトに属しているか確認する。
- 現在のディレクトリまたはその親ディレクトリが Git ワークツリーであるか、`flake.nix` が存在する場合は、プロジェクトとして扱う。
- Git ワークツリー内では、Git のトップレベルをプロジェクトルートとする。Git ワークツリー外では、現在のディレクトリから最も近い、`flake.nix` が存在する親ディレクトリをプロジェクトルートとする。
- プロジェクトのルートに `AGENTS.md` が存在しない場合は、作業を始める前に作成する。
- 新しく作成する `AGENTS.md` には、確認できたプロジェクト固有の構成、規約、検証コマンドだけを記載する。不明な内容を推測して記載しない。
- 現在のディレクトリがプロジェクトに属していない場合は、`$CODEX_HOME/flake.nix` を作業環境として使用する。`CODEX_HOME` が未設定の場合は `~/.codex/flake.nix` を使用する。
- プロジェクトに `flake.nix` が存在しない場合は、プロジェクトのルートに作成する。
- プロジェクトで作業する場合は、作業で使用するすべてのツールを、そのプロジェクトの `flake.nix` に宣言する。
- プロジェクト以外で作業する場合は、作業で使用するすべてのツールを、`$CODEX_HOME/flake.nix` に宣言する。`CODEX_HOME` が未設定の場合は `~/.codex/flake.nix` に宣言する。
- プロジェクトルートに `flake.nix` があり、`nix`、`direnv`、および `nix-direnv` の `use flake` が利用可能な場合は、プロジェクトルートの `.envrc` に `use flake` が記載された状態にする。`flake.nix` を新規作成した場合も、これらが利用可能な場合に限り同様にする。既存の `.envrc` がある場合は、その内容を保持したまま必要な記述を追加する。
- `.envrc` が flake の開発環境を指定している場合は、作業で使用する CLI ツールをその開発環境に追加する。開発環境が指定されていない場合は、デフォルトの dev shell に追加する。
- 作業中に直接実行するすべての CLI ツールを `flake.nix` に宣言する。これにはシェル、標準的なコマンドラインユーティリティ、ビルド、テスト、整形、検査に使用するコマンドを含む。
- シェル組み込みコマンドを使用する場合は、組み込みコマンドを提供するシェル自体を `flake.nix` に宣言する。組み込みコマンドを個別のツールとして宣言する必要はない。
- 現在の実行環境が Nix 環境でない場合でも、作業で使用するツールに合わせて所定の `flake.nix` を追記または修正する。
- `flake.nix` に宣言されていないツールを、その場限りの環境構築コマンドで導入して使用しない。
- `flake.nix` の入力を追加または変更した場合は、`flake.lock` を更新して同期する。既存の入力を不必要に更新しない。
- `flake.nix` を変更した場合は、構文評価、`nix flake check`、およびプロジェクトで定められたビルドやテストを実行して検証する。検証を実行できない場合は、未実行の項目と理由を報告する。
